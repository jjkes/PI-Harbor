# 协同模式

协同模式为一段本地 Desktop 对话提供可选的子代理卡组和实时委派图，同时只额外
放开一层严格受限的委派：主 agent（L0）可以启动 L1 成员，L1 可以启动 L2 成员。
L2 永远不会获得委派工具。

Remote 和 Native Pi 对话不支持此功能。关闭协同模式时，现有会话保持原来的单层
行为。

## 开启并编辑卡组

点击对话顶栏的「协同模式」，或使用可配置的 `toggleTeamMode` 快捷键（默认
Ctrl/Cmd+Shift+T）。首次开启会按目录顺序播种当前所有已启用的子代理定义。
关闭后再开启会保留原卡组。

打开卡组管理界面可以添加或移出成员。每张成员卡都有独立的模型选择器：

- 「定义默认模型」保留定义 pin 和常规降级；定义未指定模型时继承会话模型。
- 卡上的显式选择会锁定该 provider/model 并清除定义降级，调用方不能通过
  `Task.model` 覆盖它。

只有卡组成员可以被调度。定义缺失、已禁用、模型无法解析或超出预算的成员会在
启动时被排除并记录诊断。有意清空的卡组会让主 agent 独立工作。

卡组和启用状态的修改立即保存，但从下一条消息开始生效；它们不会改写运行中回合
的目录，也不会停止现有委派。

## 查看并控制执行

调用图展示真实发生的委派，而不只是卡组。它按 Main → L1 → L2 显示每个节点的
模型、状态、耗时和嵌套数。回合箭头可浏览已加载历史，「回到实时」返回最新回合。

点击节点会打开对应的子代理工作面板标签。键盘用户可用方向键和 Home/End 遍历
树，再按 Enter 或 Space。运行中节点的「Stop」会取消该节点的整棵子树。

L1 会等自己的子节点交回报告后，才把结果交给 L0。重启后，调用图和卡组会从
持久化的转录与会话配置重建。未能启动 agent 的失败 Task 调用不会画成委派节点。

为限制权限和成本：

- 最多两层委派，且不受模型指令影响；
- 每个 L1 单次运行最多启动 4 个子节点；
- 现有的每会话 10 个运行中委派上限统计所有深度；
- 只读 L1 只能启动只读成员。

## 调整布局

团队面板位于对话和输入框左侧，对话区至少保留 450px：

- **716px 及以上：**显示可调宽的内嵌团队面板（默认 320px，最小 260px）；
- **500–715px：**显示 44px 窄栏和打开按钮；
- **低于 500px：**面板退出布局流，由顶栏以抽屉打开。

拖动分隔条或使用其方向键调整宽度。首选宽度跨会话共享并跨重启保存，临时响应式
折叠不会覆盖它。
