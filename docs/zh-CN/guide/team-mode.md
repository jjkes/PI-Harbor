# 协同模式

协同模式将一段本地 Desktop 对话变成团队。主 agent（L0）会把你的请求拆成有界任务，
委派给你开启的成员，并检查他们的报告。只允许再增加一层严格受限的委派：L1 成员可以
启动 L2 成员，L2 永远不会获得委派工具。

Remote 和 Native Pi 对话不支持此功能。关闭协同模式时，会话保持原来的单层行为。

## 开启团队

打开 Composer 下方的模式菜单，也就是显示 Agent、Plan 或 Goal 的芯片，然后选择
「团队」。可配置的 `toggleTeamMode` 快捷键（默认 Ctrl/Cmd+Shift+T）执行相同操作。
团队可与三种模式中的任意一种组合，开启时芯片会显示一个小的「团队」徽标。在新对话中，
该菜单项在发送第一条消息后才可用。

开启团队后，对话左侧会显示团队视图。窄窗口中它会以抽屉打开，顶栏的面板按钮可以再次
显示或隐藏抽屉，而不会关闭团队。

首次在对话中开启团队时，设置中所有已启用的子代理角色都会开启。关闭团队会保留成员及
其设置，供下次开启时使用。

## 选择成员

团队视图为「设置 → 子智能体」中定义的每个子代理角色显示一张卡片。卡片上的开关决定
主 agent 能否在这段对话中调用该成员。角色在设置中创建、编辑和删除，而不是在团队视图中
操作。在设置中停用的角色仍会列出，但显示为暗淡状态且开关禁用。稍后创建的角色在现有
团队对话中默认关闭。

卡片上方的标题显示已开启的成员数。选择该标题可折叠卡片，为调用图留出更多空间；此选择
会被记住。

## 为本对话配置成员

选择卡片可打开成员面板。「角色设定」按设置中的定义展示角色：描述、指令、模型、推理强度、
可用工具，以及内置角色的权限作用域。「在设置中编辑角色」会打开「设置 → 子智能体」。

「本会话临时配置」只更改此对话中的成员：

- **模型：**选择「跟随角色」，或选择 provider/model。选定模型还会清除角色的备用模型，
  主 agent 无法覆盖它。
- **推理强度：**选择「跟随角色」，或选择一个级别。该级别仍受模型支持范围的上限限制。
- **可用工具：**选择「跟随角色」，或自定义一组工具，也可以选择包含「继承主会话工具」。
  授予写入工具会使成员在这段对话中可写，成员面板会明确提示这一点。

修改过的字段会标记为「已修改」，「恢复角色默认」会清除这些修改。这些设置绝不会改变角色
或其他对话，成员关闭时也会保留它们。成员及其设置的更改会立即保存，并从下一条消息开始
生效；它们不会停止已经在运行的成员。

已关闭、在设置中停用、无法解析或超出 provider 预算的成员无法被调用。没有成员开启时，
主 agent 会独立工作。

## 主 agent 如何与团队协作

团队开启时，主 agent 默认进行委派。它只直接处理需要向你提问、撰写任务简报所需的查询、
整合报告和最终验证。它只调用已开启的成员，为每个成员提供自包含的任务简报，并行运行
独立任务，并由自己或另一名成员检查每份报告，因为成员绝不会验收自己的输出。成员会遵守
请求范围，并把需要你决定的事项交回主 agent。团队开启时，主 agent 无法使用其他生成
agent 的工具，例如 Session Orchestrator 的 `SessionTask`。

## 查看并控制执行

调用图展示真实发生的委派，而不是成员卡片。它按 Main → L1 → L2 显示每个节点的模型、
状态、耗时和嵌套数。回合箭头可浏览已加载历史，「回到实时」返回最新回合。

点击节点会打开对应的子代理工作面板标签。键盘用户可用方向键和 Home/End 遍历树，再按
Enter 或 Space。运行中节点的「Stop」会取消该节点的整棵子树。

L1 会等自己的子节点交回报告后，才把结果交给 L0。重启后，调用图和成员设置会从持久化的
转录与会话配置重建。未能启动 agent 的失败 Task 调用不会画成委派节点。

为限制权限和成本：

- 最多两层委派，且不受模型指令影响；
- 每个 L1 单次运行最多启动 4 个子节点；
- 现有的每会话 10 个运行中委派上限统计所有深度；
- 只读 L1 只能启动只读成员。

## 调整布局

团队视图位于转录和 Composer 左侧，对话区至少保留 450px：

- **716px 及以上：**显示可调宽的内嵌团队面板（默认 320px，最小 260px）；
- **500–715px：**显示 44px 窄栏和打开按钮；
- **低于 500px：**面板退出布局流，由顶栏以抽屉打开。

拖动分隔条或使用其方向键调整宽度。首选宽度跨会话共享并跨重启保存，临时响应式折叠不会
覆盖它。
