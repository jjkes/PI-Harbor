# 浏览器 Web 访问安全规格

> **翻译说明：** 本页是与 [英文源规格](/spec/05-security/03-web-access-security) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。


- 状态：已实现
- 决策：ADR 0342
- 适用于：Electron Main 中的 HTTPS 监听器，它向已登录的浏览器提供桌面
  渲染器，并承载浏览器桥接
- 不涵盖：RACP 远程控制，其规格见
  [02-remote-control-security.md](/zh-CN/spec/05-security/02-remote-control-security)

## 1. 信任模型

已登录的浏览器就是所有者。它不是独立主体，也没有降权角色：除了操作此
计算机自身的屏幕和设备或更改 Web 访问本身之外，它可以执行桌面窗口能够
执行的操作。以下控制措施阻止非所有者登录，并将已登录页面的权限限制在
该页面内。

| 威胁 | 控制措施 |
|---|---|
| 密码猜测 | 至少 10 个字符、scrypt、按地址锁定、并行检查数量上限 |
| 网络窃听 | 仅限 HTTPS；设置中显示自签名证书的指纹 |
| 跨站请求和 WebSocket 劫持 | `SameSite=Strict` cookie、`Origin` 必须等于 `Host`、CSRF 子协议 |
| 令牌经 URL、日志或引用来源泄露 | 令牌仅通过 cookie、文档 meta 标签和子协议传输；`Referrer-Policy: same-origin` |
| 框架嵌入 | `frame-ancestors 'self'`、`X-Frame-Options: SAMEORIGIN` |
| 已登录浏览器将所有者锁在外面 | Web 访问设置仅限桌面端 |
| 停滞或滥用的标签页 | 帧和缓冲区上限、心跳 |

## 2. 监听器

- 监听器必须保持关闭，直到所有者启用它；所有者关闭它时必须停止。
- 它必须仅提供 HTTPS，并使用 TLS 1.2 或更新版本。
- 根据所有者的选择，它绑定所有接口或 IPv4 回环地址，端口范围为
  1024 至 65535。
- 自签名证书（ECDSA P-256，有效期 397 天）在首次启动时生成，并在到期前
  30 天内续期。其私钥文件必须仅所有者可读。所有者提供的证书必须在
  监听器启动前与其私钥匹配。
- 如果请求的 `Host` 不是可带可选端口的主机名或 IP 字面量，必须拒绝该请求。

## 3. 凭据

- 仅有一个账户：用户名最多 64 个字符且不得包含控制字符，密码长度为
  10 至 256 个字符。
- 密码必须仅以 scrypt（N = 32768，r = 8，p = 1，16 字节盐，32 字节密钥）
  的形式存储在仅所有者可访问的文件中。如果存储哈希的参数超过 N = 2^17、
  r = 16 或 p = 4，必须在不执行密钥派生的情况下拒绝该哈希。
- 用户名和密码的比较必须采用恒定时间，用户名错误时也必须消耗与密码
  错误时相同的 scrypt 工作量。

## 4. 登录限流

- 每次尝试都必须在校验密码前预留一个槽位，使并行请求不能赶在失败计数
  更新之前执行。
- 同一客户端地址失败五次后，必须将该地址锁定 15 分钟。IPv6 地址按其
  /64 前缀计数；IPv4 映射地址按 IPv4 计数。
- 最多同时校验四个登录请求；更多尝试会得到“busy”响应。登录请求体不得
  超过 8 KiB。

## 5. 会话

- 会话令牌是 32 个随机字节。宿主必须仅在内存中保存其 SHA-256 哈希。
- cookie 必须为 `__Host-pi-web-session`、`Secure`、`HttpOnly`、
  `SameSite=Strict` 和 `Path=/`，且不得包含 `Domain`。
- 会话必须在连续 24 小时无活动后、登录满 7 天后、退出登录时以及应用
  重启时结束。用户名或密码更改时、Web 访问关闭时，以及所有者将所有
  浏览器退出登录时，所有会话都必须结束。结束会话必须以代码 4401 关闭其
  桥接 socket。

## 6. 请求完整性

- 登录、退出登录和 WebSocket 升级必须要求 `Origin` 等于 `https://` 后接
  `Host` 组成的值。
- 升级必须要求有效的会话 cookie，并要求与 `pi-web.v1` 一起通过
  `pi-csrf.<token>` 子协议提供该会话的 CSRF 令牌。令牌比较必须采用
  恒定时间。
- CSRF 令牌只能在经过身份认证的文档中下发。任何会话令牌或 CSRF 令牌
  都不得出现在 URL 中。
- 每个响应必须携带 `X-Content-Type-Options: nosniff`、
  `Referrer-Policy: same-origin`、`X-Frame-Options: SAMEORIGIN`、
  `Content-Security-Policy: frame-ancestors 'self'` 和
  `Cross-Origin-Opener-Policy: same-origin`。文档和 API 响应不得被缓存。
  登录页面不得运行脚本。
- 未登录的导航必须重定向到登录页面；其他所有未登录请求必须返回 401。

## 7. 通道和事件策略

- 桥接器必须仅分发渲染器调度器注册的 `IPC.invoke` 通道，并排除
  `channel-policy.ts` 中的拒绝集合。事件通道名称和未知名称必须返回
  `UNSUPPORTED`，且不得到达处理程序。
- 拒绝集合必须包括原生对话框、窗口和开发者工具控制、退出应用、在操作系统中
  显示或打开路径、内置浏览器面板、语音采集、存储位置迁移，以及
  `webAccess` 命名空间。
- Web 访问设置 IPC 必须要求发送方为主窗口。
- `webAccessChanged` 和 `liveVoicePort` 不得转发给浏览器。

## 8. 资源上限

- 桥接帧不得超过 64 MiB。
- 未发送数据超过 32 MiB 的标签页必须断开连接。
- 必须每 30 秒向每个 socket 发送一次 ping，并在其漏掉 ping 或会话结束时
  断开连接。

## 9. 日志

登录成功、失败和锁定会连同客户端地址键一起记录日志。不得记录密码、
提交的用户名、cookie、CSRF 令牌和请求体。

## 10. 残余风险

- 任何获知密码的人都能在所有者的权限设置范围内，通过 Agent 控制此计算机。
- 如果不比对指纹就接受自签名证书警告，首次连接在恶意网络上可能遭到拦截。
- 会话不绑定客户端地址：被盗的 cookie 在会话结束前可从任何位置使用。
- DNS rebinding 可让恶意页面以攻击者的主机名访问监听器，但该页面没有
  会话 cookie，仍必须登录。
